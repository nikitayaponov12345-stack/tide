# M0-06 — окно выбора и стройка плота

**Цель.** Новый уровень открывает окно выбора, как в оригинале: «Плот» и карточки моряка, выбор в два нажатия, недоступная карточка видна затемнённой с причиной. «Плот» открывает стройку клетки: на ПК щелчок по месту ставит сразу, на телефоне касание переносит призрак, а кнопка «Поставить» ставит его. Правила окна — GDD «Окно выбора» и решения Никиты 09.10: если свободной клетки нет, среди карточек обязательно есть «Плот».

**Что изменится в игре.** На каждом новом уровне игра встаёт на паузу. Поле затемняется, сверху — «Новый уровень!» и «Выбери улучшение». Карточек:
- на 2 уровне — одна, «Плот»;
- на 3-м — две;
- дальше — три.

На ПК карточки стоят в ряд, на телефоне — стопкой, картинка слева от текста. Нажатие на карточку подсвечивает её, и только тогда появляется кнопка «Взять». Карточка моряка сразу меняет сеть («Бросок дальше» — круг дальности +40) и возвращает игру. «Плот» включает стройку: бледно подсвечены места, куда можно поставить клетку, а призрак — зелёный там, где можно, и красный там, где нельзя.
- На ПК призрак идёт за мышью, щелчок по подсвеченному месту ставит клетку.
- На телефоне касание переносит призрак. Когда он стоит на подсвеченном месте, появляется «Поставить» — внизу по центру поля, а если кнопка закрыла бы призрак, то вверху.

Отмены у стройки нет. Несколько уровней подряд — несколько окон подряд. Баннер «Новый уровень!» над полосой опыта убирается: эту роль теперь играет окно. Версия — 0.0.4: в `main.ts`, `package.json` и в двух полях `version` в `package-lock.json`, как в M0-05.

Условие: M0-05 сделана. Перед началом прочитай:

## 1. Плот — `src/core/raft.ts`

Половина сетки `half` = (`raft_grid` − 1) / 2, то есть 4. Новые методы:
- `has(gx, gy)` — есть ли клетка.
- `canAdd(gx, gy)` — можно поставить новую клетку. Нужно, чтобы:
  - `|gx| ≤ half` и `|gy| ≤ half`;
  - место было свободно;
  - рядом по стороне была клетка. Соседство по диагонали не считается — как `Qh` у оригинала.
- `candidates(): Cell[]` — все места, где `canAdd`, по порядку: сначала по `gy`, потом по `gx`. У одной клетки их 4.
- `add(gx, gy): boolean` — ставит клетку, если `canAdd`, иначе возвращает `false`.
- `freeCells(): number` — целые клетки без постройки, для правила «Требуется свободный плот». В M0 построек и урона нет, поэтому это все клетки. Считается ли центральная клетка, Никита решит до M1; сейчас — как у оригинала, считается.

## 2. Колода — `src/core/deck.ts` (новый)

`Deck(data, locationId, rng, kinds)` — что предлагать в окне и сколько раз что взято в локации. `kinds` — виды карточек, которые сейчас в игре. `Game` передаёт `['raft', 'sailor_upgrade']`: постройки и их улучшения придут в M1 вместе с механиками. У колоды свой `Rng` с сидом `seed + 1` (ARCHITECTURE, инвариант 3).

Методы:
- `card(id)` — строка `cards.csv`, нет такой — ошибка;
- `size(level)` — `window_cards_level2` на 2 уровне, `window_cards_level3` на 3-м, иначе `window_cards`;
- `take(id, level)` — учесть взятие;
- `taken(id)` — сколько раз взята;
- `offer(level, ctx): OfferCard[]`, где `OfferCard = { id, available, reason }`.

`reason` — ключ строки или `null`. Контекст:
```ts
interface DeckContext {
  freeCells: number;                // raft.freeCells()
  canAddCell: boolean;              // raft.candidates().length > 0
  has(building: string): boolean;   // такая постройка стоит на плоту (в M0 — всегда false)
  spearOwned: boolean;              // у моряка есть копьё (с M0-08)
  bossVisitSeen: boolean;           // был визит босса (M1)
}
```

**Карточку можно предложить** на уровне L, когда выполнено всё:
- её `kind` — среди `kinds`;
- для `raft` — `ctx.canAddCell` («карточка, которая ничего не меняет, не предлагается»);
- `max_per_location` пуст или взятий меньше;
- `min_level_gap` пуст, карточку ещё не брали или L − уровень последнего взятия ≥ `min_level_gap`;
- `requires` выполнено:
  - `boss_visit_seen` → `ctx.bossVisitSeen`;
  - `spear_owned` → `ctx.spearOwned`;
  - `level:N` → L ≥ N;
  - `has:X` → `ctx.has(X)`;
  - другое значение — ошибка.

**Карточка доступна**, если её можно взять сейчас. Постройку (`building`) без свободной клетки взять нельзя: `{ available: false, reason: 'ui.need_free_cell' }`. Остальные виды всегда доступны.

**Окно уровня L** — по шагам, как `ol` у оригинала, плюс решение 09.10:
1. n = `size(L)`; пул — все карточки, которые можно предложить, в порядке файла.
2. Выбор без возвращения по весам: вес = `card_weight_<kind>`. min(n, размер пула) раз: r = `rng.next()` × сумма весов оставшихся, идти по пулу, пока r не уйдёт ниже нуля, — карточка выбрана и выходит из пула.
3. Принудительная карточка — первая строка `forced_cards.csv` с этой локацией и триггером `level:L`. Если её нельзя предложить, принудительной карточки нет. Если её нет среди выбранных, она встаёт вместо последней выбранной — даже если сама недоступна, как у оригинала.

   Её можно предложить, значит она есть в пуле. Если пул меньше n, выбраны все его карточки, и она уже среди них, — поэтому ветки «добавить в конец» не нужно. Триггер `after:boss_visit` придёт вместе с боссами (M1); сейчас он не срабатывает.
4. Решение Никиты 09.10. Если `ctx.freeCells` = 0, «Плот» можно предложить и его нет среди карточек, он встаёт вместо последней непринудительной карточки. Если все принудительные — вместо последней. Ветки «добавить в конец» тоже не нужно — по той же причине. Окно может выйти таким: «Плот» и две затемнённые постройки.
5. Устойчивая сортировка: доступные — первыми.
6. Если доступной карточки нет — вернуть `[]`: такое окно не открывается (CLAUDE.md, правило 6). В M0 так не бывает раньше уровня ~100.

## 3. Окно и стройка в ядре — `src/core/game.ts`

- `progression.ts`: новый метод `addXp(amount)` — прибавить опыт и обработать новые уровни (цикл из `step`); `step` вызывает его. Других изменений нет.
- Поля `Game`:
  - `deck`;
  - `window: { level: number; cards: OfferCard[] } | null` — на каждое окно новый объект;
  - `build: { card: string } | null`;
  - очередь уровней, чьи окна ещё не показаны.

  `get paused()` — открыто окно или идёт стройка.
- `step(dtMs)`: на паузе ничего не делает — время мира, `stats.gameMs`, предметы, сеть и значки стоят. Иначе — как сейчас, а в конце:
  1. уровни из `progression.takeLevelUps()` уходят в очередь, а уровень мира подтягивается к уровню прогрессии;
  2. открывается следующее окно.

  Несколько уровней за шаг дают несколько окон подряд.
- Окно открывается, пока не пауза и очередь не пуста: `deck.offer(L, ctx)`. Пустой ответ — уровень без окна, и в том же вызове берётся следующий из очереди.
- `takeCard(i): boolean` — карточка `i` из `window.cards` (в порядке показа). Окна нет, индекса нет или карточка недоступна → `false`.

  Порядок важен: сначала проверки и расчёт, потом изменения. Ошибка должна оставить окно открытым, а карточку — невзятой.
  1. Для `sailor_upgrade` — посчитать новые параметры сети.
     - Показатели: `net_radius` → `radius`, `net_capacity` → `capacity`, `throw_range` → `range`, `pull` → `pull`.
     - Режимы: `add` — прибавить `value`; `mul` — умножить на (1 + `value`); `set` — заменить на `value`.
     - Другой показатель (`spear_damage` — с M0-08) или другой вид, кроме `raft` (постройки — M1), → `throw new Error`.
  2. `deck.take(id, L)` и `window = null`.
  3. `raft` → `build = { card: id }`, игра остаётся на паузе. Карточка моряка → новые параметры сети, затем следующее окно из очереди.
- `placeCell(gx, gy): boolean` — стройки нет или `!raft.canAdd` → `false`. Иначе клетка ставится, `build = null`, и открывается следующее окно из очереди.
- `throwTo` на паузе возвращает `false` и бросок не считает. `setPull` работает всегда: отпускание пальца во время окна должно выключить удержание.
- `debugLevelUp()` — опыт до следующего уровня сразу, через `progression.addXp`; окно открывается тут же, не дожидаясь `step`. В `stats.xpGained` этот опыт не входит.

## 4. Ввод в стройке — `src/game/input/build.ts` (новый) и `pointer.ts`

- `BuildCursor(cellPx)` — призрак стройки, состояние слоя ввода, а не ядра.
  - Поля: `gx`, `gy`, `shown`, `byTouch`.
  - `point(x, y, type)`: `gx = round(x / cell_px)`, `gy = round(y / cell_px)` (без −0), `shown = true`, `byTouch = type !== 'mouse'`.
  - `reset()`: `shown = false`, `byTouch = false`.

  `main.ts` вызывает `reset()`, когда начинается стройка (появился новый объект `game.build`).
- `PointerInput` получает курсор четвёртым аргументом конструктора и теперь слушает и `pointermove`. Жест, нажатие которого пришлось на стройку (`game.build !== null` на `down`), идёт в стройку, а не в `Gesture`:
  - `down` — `cursor.point`;
  - `move` — `cursor.point`: у мыши — при любом движении, даже без нажатия (наведение); у пальца и пера — пока он прижат;
  - `up`:
    - `cursor.point`;
    - у мыши — `game.placeCell(cursor.gx, cursor.gy)`. ПК ставит по отпусканию, как у оригинала; щелчок не по подсвеченному месту ничего не делает;
    - у пальца и пера — только перенос призрака;
  - `cancel` — без постановки.
- Жест, начатый до стройки, доводится до конца через `Gesture`: его `up` выключит удержание, а бросок на паузе ядро не примет.
- `noteTap` — на каждое нажатие, как сейчас.
- Ввод флагом не выключать (флаг `enabled` удалён в M0-05): холст закрывает затемнение окна.

## 5. Отрисовка и окна

- `view.ts`:
  - плот — все клетки `game.raft.cells`;
  - только в стройке — бледные клетки на местах `raft.candidates()` (прозрачность около 0,2);
  - если `cursor.shown` — призрак клетки: зелёный, если `raft.canAdd(cursor.gx, cursor.gy)`, иначе красный. После стройки `shown` остаётся `true`, поэтому призрак рисуется только во время стройки.

  Сигнатура — `sync(game, cursor)`.
- `src/ui/cards.ts` (новый), класс `CardWindow` — окно выбора, вёрсткой поверх холста:
  - **Затемнение.** 70 % на весь экран, `pointer-events: auto`: холст под окном не получает нажатий.
  - **Заголовок.** Две строки: `ui.new_level` крупно и `ui.choose_card`.
  - **Карточка.**
    - Картинка: до этапа арта — цветной квадрат по виду (`raft` — цвет плота, `sailor_upgrade` — синий, `building` — зелёный, `building_upgrade` — оливковый; это константы вёрстки).
    - Название (`name_key`) и одна фраза (`desc_key`).
    - Недоступная карточка — прозрачность 0,65, вместо фразы — причина (`reason`, красным); её нельзя выбрать.
  - **Раскладка.** `landscape` — карточки в ряд, `portrait` — стопкой, картинка слева от текста. Совет: раскладывать окно в точках поля дизайна и масштабировать так же, как холст (`fitDesign`). Тогда оно помещается целиком в любом окне — так сделала пробная сборка.
  - **Выбор.** Нажатие на доступную карточку подсвечивает её и показывает «Взять» (`ui.take`). Нажатие на другую карточку переносит выбор. Где «Взять»:
    - в ряду — под выбранной карточкой; место под кнопку есть под каждой карточкой, поэтому ничего не сдвигается;
    - в стопке — под стопкой.

    «Взять» вызывает `game.takeCard(i)` — только для своего окна: нажатие, пришедшее, когда `game.window` уже другое, ничего не делает.
  - **Защита от двойного нажатия.** 300 мс после появления окна карточки и кнопка неактивны: отпускание пальца, начатое на поле, не выбирает карточку. Эти 300 мс — по часам браузера (`performance.now()` в слое интерфейса), а не по игровому времени: в окне оно стоит.
  - **Помещается целиком** в обе раскладки (TESTPLAN, «Интерфейс до этапа арта»).
  - **Перестройка.** Новое окно (новый объект `game.window`) — окно строится заново, выбор и защита начинаются сначала. Смена раскладки при том же окне — тоже строится заново, но выбор и время начала защиты сохраняются.
- `src/ui/place.ts` (новый), класс `PlaceButton` — кнопка «Поставить» (`ui.place`).
  - **Когда видна:** идёт стройка, `cursor.shown`, `cursor.byTouch` и `raft.canAdd(cursor.gx, cursor.gy)`. На ПК её не видно, как у оригинала.

## 6. Сигналы площадке — `control.ts`

Как у оригинала:
- окно открылось — `gameplayStop()`;
- окно закрылось после «Взять» — `gameplayStart()`, даже если дальше стройка. В стройке сигналов нет.

Сигналы — только после первого нажатия игрока (`notePlay`). Правила для `Control`:
- в конце `frame()` сравнивать объект `game.window` с прошлым кадром:
  - было окно — `gameplayStart`;
  - стало окно — `gameplayStop`;
  - смена окна на следующее — оба по порядку;
- первое нажатие при открытом окне: игрок считается играющим, но `gameplayStart` не шлётся — он придёт, когда окно закроется.

## 8. Тесты

В каждом цикле тестов — предел числа шагов: синхронный бесконечный цикл Vitest не прерывает по тайм-ауту, весь `npm run test` просто висит.

- `tests/unit/game.test.ts`, тест «темп: «рука» за 60 с…». Сейчас он крутится, пока `gameMs < 60 000`, но на 2 уровне окно ставит игру на паузу, `gameMs` перестаёт расти, и тест висит навсегда (так было в пробной сборке). «Рука» должна на паузе выбирать сразу:
  - в окне — `takeCard(0)`;
  - в стройке — `placeCell` на первое место из `raft.candidates()`.

  Время 2-го уровня в `build/probe/m0-02-game.json` при этом не меняется: паузы в игровое время не входят.
- `tests/unit/raft.test.ts`:
  - у одной клетки 4 места, по порядку;
  - диагональ — нельзя, занятое — нельзя;
  - цепочка до `gx = half` — можно, `half + 1` — нельзя;
  - `add` на неверное место — `false`, клеток не прибавилось;
  - `freeCells` = число клеток.
- `tests/unit/deck.test.ts` (новый). Колода с `Rng` от явного сида; для видов M0 и для всех видов. Проверить:
  1. Размеры: на 2 уровне — 1, на 3-м — 2, на 4-м — 3.
  2. На 2 уровне — всегда `[raft]` (100 сидов).
  3. С видами M0 постройки и их улучшения не попадаются ни разу (1000 окон на уровнях 4–10).
  4. `throw_farther` после 13 взятий не предлагается.
  5. `spear_stronger` — только при `spearOwned` (все виды).
  6. Улучшение постройки — только при `has`.
  7. `whirlpool` (`level:6`) — не раньше 6 уровня.
  8. `min_level_gap` и `boss_visit_seen`: копейная башня и её улучшение.
