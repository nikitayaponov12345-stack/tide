# M1-05 — постройки на клетках и карточка сетевой башни

**Цель.** Постройки из GDD («Плот и постройки», решение Никиты 09.10): на клетке одна постройка, и встаёт она на любую целую клетку — в том числе на центральную и под моряком. Первая постройка — сетевая башня: в Лагуне её карточка принудительная на 4-м уровне («Прогрессия в локации», окно выбора). Враги приходят чаще с каждой постройкой («Угрозы»: интервал 30 с / (1 + 0,5 × число построек), не чаще раза в 5 с). Ловить башня начнёт в M1-06.

**Что изменится в игре.**
- В окне 4-го уровня всегда есть «Сетевая башня». Дальше она может выпасть в любом окне, как другие карточки; до 4-го уровня её нет.
- «Взять» на башне открывает стройку, как у «Плота». Подсвечены свободные целые клетки, в том числе центральная и клетка под моряком. Мышь ставит башню по отпусканию, палец переносит призрак, ставит кнопка «Поставить».
- Башня на клетке — бирюзовый круг, на разбитой клетке — бледный. Пока башня стоит без дела.
- Клетка с постройкой больше не свободна. Если свободных клеток нет, башня в окне затемнена с надписью «Требуется свободный плот», а «Плот» в окне есть — как и было по правилу окна.
- Крабы приходят чаще: с одной постройкой раз в 20 с, с двумя — раз в 15 с. Если с прошлого краба прошло больше нового интервала, следующий придёт сразу после стройки.
- По клетке с постройкой моряк ходит, как по свободной.
- Версия — 0.0.12: в `main.ts`, `package.json` и в двух полях `version` в `package-lock.json`.

## 2. Клетки — `raft.ts`

- `Cell` — `{ gx, gy, hp, building }`: `building` — id постройки из `buildings.csv` или `null`. Центральная и новая клетка — `null`.
- `canBuild(gx, gy)` — клетка есть, цела и без постройки. Центральная и клетка под моряком подходят.
- `build(gx, gy, id): boolean` — поставить постройку; нельзя по `canBuild` — `false`.
- `buildSpots(): Spot[]` — места для постройки: свободные целые клетки, по `gy`, потом по `gx`.
- `buildingCount()` — сколько построек, в том числе на разбитых клетках; `hasBuilding(id)` — есть ли такая постройка, тоже и на разбитой клетке.
- `freeCells()` — целые клетки без постройки.
- `restore`: клетка без `building` (запись M1-01…M1-04) получает `null` — правило 5 в `CLAUDE.md`.
- `stage` принимает `{ gx, gy, hp }`: в `raft.test.ts` его зовут без `building`.

## 3. Колода — `deck.ts`

- Пятый параметр конструктора — список построек, которые можно предлагать в этой локации. По умолчанию `null` — любые: так старые тесты колоды не меняются.
- `canOffer`: у карточек `building` и `building_upgrade` при списке не `null` — `target` должен быть в списке.

## 4. Ядро — `game.ts`, `enemies.ts`

- Виды карточек в игре — `raft`, `building`, `sailor_upgrade`. Улучшения построек придут в M1-06.
- `BUILDINGS_IN_GAME = ['net_tower']` — постройки, которые уже можно ставить. Список для колоды: `new_buildings` локаций с `order` не больше нынешней, из тех, что в игре. В Лагуне это одна `net_tower`.
- `takeCard`: карточка постройки открывает стройку `{ card }`, как «Плот». Постройка не из `BUILDINGS_IN_GAME` → throw.
- `placeCell(gx, gy)`: у «Плота» — новая клетка, как сейчас; у постройки — `raft.build(gx, gy, card.target)`: `target` карточки — id постройки из `buildings.csv`. Место не подходит или открыта пауза → `false`, стройка остаётся.
- `canPlace(gx, gy)` и `buildSpots()` — по карточке стройки: у «Плота» — `raft.canAdd` и `raft.candidates()`, у постройки — `raft.canBuild` и `raft.buildSpots()`. Стройки нет — `false` и `[]`. Паузу `canPlace` не смотрит: её проверяет `placeCell`, как раньше.
- `deckContext`: `has` — `raft.hasBuilding`.
- `EnemiesContext` — поле `buildings?: number`; нет поля — 0, так старые тесты врагов не меняются. `Game` передаёт `raft.buildingCount()`, `Enemies.step` берёт интервал `intervalMs(ctx.buildings ?? 0)`.
