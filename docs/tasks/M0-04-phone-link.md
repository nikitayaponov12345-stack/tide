# M0-04 — сборка по ссылке для телефона

**Цель.** Игра открывается на телефоне по ссылке `https://nikitayaponov12345-stack.github.io/tide-play/`: команда `npm run publish` собирает игру и отправляет `dist/` в отдельный открытый репозиторий `tide-play`, который отдаёт GitHub Pages. Так же устроено в «Кальдере» (`ships-play`): основной репозиторий может оставаться закрытым, а Pages на бесплатном тарифе работает только для открытых.

**Что изменится в игре.** В отладочной строке после версии — метка сборки: `Прилив 0.0.2 (a0fa004) · …` — короткий хеш коммита, из которого собрана опубликованная сборка, со знаком `+`, если были незакоммиченные правки; в `npm run dev` и в сборке без публикации — `(dev)`. По метке Никита видит на телефоне, какая сборка открыта. На телефоне и в узком окне предметы, сеть и значки больше не видны в тёмных полосах за краем поля.

Условие: M0-03 сделана. Перед началом прочитай `CLAUDE.md`, `docs/ARCHITECTURE.md` (§2, §9), `vite.config.ts` и `src/main.ts`. Репозиторий `tide-play` на GitHub создаёт Никита; отправку в него (`npm run publish` без `--dry-run`) делает тоже Никита — это push.

**Проверка до передачи (08.10).** Пробной сборки не было — это инструмент без новой механики. Прототип Claude на копии кода после M0-03: публикация в локальный «голый» репозиторий (один коммит, 11 файлов вместе с `.nojekyll`), метка сборки попала в код и в отладочную строку, маска поля на снимке телефона работает; Vitest 74 из 74, Playwright 10 сценариев, сборка 0,57 МБ.

## 1. Публикация — `tools/publish.mjs`

Node ESM без зависимостей. Запуск: `npm run publish` — собрать и отправить; `npm run publish -- --dry-run` — всё, кроме `git push`. Шаги по порядку:

1. **Метка сборки:** `git rev-parse --short HEAD` в корне репозитория; если `git status --porcelain` не пустой — к метке `+`. Версия — поле `version` из `package.json`.
2. **Сборка:** `npm run build` с переменной окружения `VITE_BUILD=<метка>` (Vite отдаёт её игре как `import.meta.env.VITE_BUILD`). Вывод сборки — в консоль как есть.
3. **Проверка путей:** в `dist/index.html` нет абсолютных путей (`src="/…"`, `href="/…"`, кроме `//`): страница живёт по адресу `…/tide-play/`. Нашлись — ошибка «нужен base: "./" в vite.config.ts», выход с кодом 1 (сейчас `base: './'` уже стоит — не менять).
4. **Чистая папка** `build/publish/` (папка `build/` в `.gitignore`): удалить целиком, скопировать в неё содержимое `dist/`, добавить пустой файл `.nojekyll` (без него GitHub Pages прячет файлы и папки, начинающиеся с `_`). На Windows файлы прежнего `build/publish/.git/objects` — только для чтения: `rmSync(…, { recursive: true, force: true })` обычно справляется; если нет — снять атрибут (`chmodSync`) и повторить.
5. **Отдельный репозиторий из одного коммита** в `build/publish/`: `git init -b main`, `git add -A`, `git commit -m "Прилив <версия> (<метка>) <дата и время по часам ноутбука>"`, затем `git push --force <адрес> main`. История `tide-play` каждый раз заменяется целиком — так и задумано. Адрес — `https://github.com/nikitayaponov12345-stack/tide-play.git`, переменная окружения `TIDE_PUBLISH_REMOTE` его заменяет (для проверки на локальном репозитории).
6. **Итог в консоль:** сколько файлов отправлено, ссылка `https://nikitayaponov12345-stack.github.io/tide-play/?v=<метка>` (параметр `v` обходит кэш страницы на телефоне — GitHub Pages держит её до 10 минут) и строка «GitHub Pages обновляет страницу 1–2 минуты; в отладочной строке игры — метка сборки». С `--dry-run` — одна строка: версия, метка, число файлов, адрес и «push не делался».

Любая команда git или npm с ненулевым кодом — сообщение с её выводом и выход с кодом 1. Windows: `npm` запускается через `npm.cmd`, поэтому `spawnSync(…, { shell: process.platform === 'win32' })`; пути — через `node:path`.
