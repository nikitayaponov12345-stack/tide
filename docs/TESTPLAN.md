# TESTPLAN — «Прилив» (v1.10, 10.10.2026)

Шесть уровней проверки. Ошибка, найденная на любом уровне, сначала становится тестом, который падает, потом исправляется.

## 1. Тесты ядра — Vitest (`npm run test`)

- На каждый модуль `src/core/` — файл `tests/unit/<модуль>.test.ts`. Новая механика приходит с тестом, который без неё падает.
- Время — только через шаги: `world.step(dtMs)` или `FixedStep.advance`; тест на независимость от частоты кадров (30, 60 и 144 кадра в секунду дают одно и то же) — для каждого модуля, который считает время.
- Случайность — только `Rng` с сидом; в тесте сид задан явно. Числа, которые зависят от бросков, проверяются либо при фиксированном сиде (таблица-сторож), либо статистически на большом прогоне с запасом.
- Числа баланса в тестах берутся из `DATA` (тот же `src/data.ts`), а не вписываются: правка таблицы не должна ломать тесты механики. Исключение — тест данных, который сторожит конкретные значения таблиц (`tests/unit/data.test.ts`).
- Предел времени `npm run test` — 30 с на ноутбуке; дольше — в `npm run sim`.
- Сохранение (`tests/unit/save.test.ts`, с M1-01; с M1-08 — и тест `game-snapshot.ts`): снимок → JSON → `restore` даёт тот же снимок; партия, загруженная в любом из 16 случаев (окно, стройка, сеть в полёте и в тяге, копьё в полёте, краб, значки, раненая клетка — с M1-03, постройка — с M1-05, сеть башни — с M1-06, шторм идёт — с M1-07, визит и ядро в полёте — с M1-08, бутылка в воде и буст идёт — с M1-11, кнопка буста за рекламу видна — с M1-12), доигрывает то же, что без перерыва. Прогон — 15 000 тактов, около 250 с игрового времени: первые шторм и шхуна приходят в нём сами. Состояние, до которого общий прогон не доходит, — отдельным тестом в том же файле, со своей подготовкой отладочными командами: с M1-09 — копьё копейной башни в полёте (игрок теста ставит башни на каждую клетку и не чинит плот, копейная у него приходит только затемнённой). Новое поле ядра входит в этот тест сразу; проверка — поломкой: без его строки в `restore` тест падает.
- Записи без полей M1-07…M1-09 проверяют тесты механик: без `events` — `events.test.ts`, без `boss` — `boss.test.ts`, без `spearTowers` и `deck.visitShown` — `spear-towers.test.ts`.

## 2. Проверка таблиц (`npm run data`)

`tools/data-check.mjs`: заголовки, типы, уникальность id, ссылки между таблицами, доли потока (100 % в каждой локации), ярусы подряд, строки ru и en у каждого ключа, межстраничная не чаще раза в 3 минуты; с M1-08 — копьё моряка достаёт шхуну (`boss_visit_gap_px` не больше наименьшей `throw_range`). Входит в `npm run check` первой.

## 3. Смоук собранной игры — Playwright (`npm run e2e`)

- Две раскладки: `desktop` 1280×720 и `phone` 412×915. Игра запускается без ошибок в консоли, мир идёт, раскладка верная, площадке ушёл `loadingFinished`.
- Браузер тестов рисует игру без видеокарты, силами процессора. Поэтому прогон идёт по одному браузеру (`workers: 1`), а у `phone` плотность пикселей 1: на раскладку и нажатия она не влияет, а точек в кадре вчетверо меньше (с 09.10, после перегрузки ноутбука). Пробой в песочнице: кадров в секунду у `phone` стало 15–20 вместо 3–4.
- Снимки — `build/shots/<задача>_<раскладка>.png`; их смотрят глазами при приёмке.
- Сценарии задач — через `window.__game` (команды и чтение состояния) и настоящие нажатия `page.mouse` / `page.touchscreen`, когда проверяется сам ввод.
- Шторм, шхуну, копейную башню, буст и предложение буста сценарии не ждут, а вызывают отладочными командами (M1-07…M1-12, оба проекта): `storm.spec.ts` — `debugEvent()` и краб: шторм идёт и убывает, снимок `m1-07_storm_<раскладка>.png` (вода темнее, краб без прозрачности); `boss.spec.ts` — `debugBossVisit('left')`: борт в круге дальности моряка, шхуна целиком в поле — `m1-08_schooner_<раскладка>.png`; `spear-tower.spec.ts` — `debugBuild(0, 0, 'spear_tower')` и краб: башня бьёт сама, моряк копья не бросал — `m1-09_spear_tower_<раскладка>.png`; `boost.spec.ts` — `debugBoost()`: в полосе опыта «Буст N с», время убывает — `m1-11_boost_<раскладка>.png`; `boost-offer.spec.ts` — `debugBoostOffer()` и два краба: нажатие на кнопку — реклама заглушки между «игра остановлена» и «игра идёт», буст, крабов нет — `m1-12_boost_offer_<раскладка>.png`; с `?rewarded=0` предложений нет. Карточку копейной башни после визита проверяют unit-тесты.
- Короткие состояния — плашку на секунду, защиту окна 300 мс — ловит `MutationObserver` в странице, а сроки удержаний и отпусканий отсчитывают таймеры в самой странице: на медленной машине обращение Playwright к браузеру идёт до 2 с.

## 4. Проба управления на телефоне и ПК (ворота M0) — пройдена 09.10

Никита попробовал прототип на телефоне и на ПК (схемы M0-03, сборка по ссылке M0-04) и 09.10 оставил классическую схему для обеих версий: «в мобильной и пк версии оставим классическую схему броска сети». Решение записано в GDD (раздел «Решения») и в CLAUDE.md; схемы Б, В, Г и сводка пробы убраны задачей M0-05. Дальше управление проверяется живой пробой после каждой вехи (§6): сборка по ссылке (`npm run publish`) или `npm run dev` по Wi-Fi (адрес Network из вывода Vite; VPN на ноутбуке выключить).

## 5. Бот и замер темпа (`npm run sim`, с M0-09)

- Бот «человек» (`src/sim/bot.ts`): реакция 0,25–0,7 с перед броском, промах — нормальный, σ 14 точек по каждой оси, 0,15–0,9 с от падения сети до тяги, 2,5–3 с на окно, 1,2–2,5 с на стройку; краба (с M1-08 — и шхуну на визите) замечает за 0,5–1 с и бьёт копьём (промах σ 12). Растит базу как живой игрок на записях: «Плот» и постройки первыми (копейная башня — сразу после сетевой, с M1-09), клетки — плотно к центру. Бутылку (с M1-11) ловит, как живой игрок, сразу: в «кучке» она стоит для него 30 опыта (`bottleValue`). Буст за рекламу (с M1-12) берёт в 3 предложениях из 7, как живой игрок на записях, кнопку замечает за 0,5–1 с; реклама по часам — 12,5–13,5 с (запись ПК) и входит в перерыв межстраничной. В M0 моряком не ходит, как боты разбора; с M1-08 ходит только к шхуне на визите: копьём не достаёт — через время реакции шагает на соседнюю целую клетку, ближе к корпусу.
- Мерит: время до 2, 10, 20 и 40 уровня (игровое и по часам вместе с окнами и стройкой), доли опыта по источникам, предметы на бросок, число рекламных точек за 10 минут, долю игрового времени.
- Прогон: ворота — 200 игр (сиды 1–200) до 2-го уровня, кривая — 20 игр до 40-го уровня или 40 минут игры. Отчёт — `build/sim/tempo.md` и `build/sim/tempo.json`.
- Ворота M0: 2-й уровень — до 10 с по медиане 200 игр; остальную кривую бот калибрует на M1, когда в игре есть постройки и враги. Ворота M1–M3: каждая локация 20–25 мин по часам, 40-й уровень — на 20–24-й минуте.

## Интерфейс до этапа арта (M4)

Окна — рабочая заготовка: окно помещается на экран в обеих раскладках, всё нажимается, случайной покупки или выбора двойным нажатием нет (подтверждение или неактивная на 0,3 с кнопка). Тест окна — поведение и «окно не больше экрана в обеих раскладках»; пиксельные проверки вида не пишем.
