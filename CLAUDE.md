# CLAUDE.md — правила для Claude Code в проекте «Прилив»

## Что это
Браузерная 2D-аркада (рабочее название «Прилив»): моряк на плоту ловит сетью плывущие предметы, растит плот и автоматику, отбивается от морских врагов и проходит кампанию из локаций по карте моря. Жанр — по мотивам Sea Catcher (Poki), но мир, модели, интерфейс, тексты и баланс свои.
Площадки первого выпуска: Яндекс Игры (через песочницу Playgama) и CrazyGames — одна сборка, связь с площадками через Playgama Bridge.
Управление — классическая схема, как в оригинале, на ПК и на телефоне (решение Никиты 09.10): бросок нажатием по воде (на телефоне — по отпусканию), подтягивание — удержанием.

## Документы
- `docs/GDD.md` — правила игры и числа (выгрузка Claude Doc «Прилив: GDD»; правится в Claude Doc, сюда — новой выгрузкой).
- `docs/ARCHITECTURE.md` — устройство кода и инварианты. `docs/ROADMAP.md` — вехи и задачи. `docs/TESTPLAN.md` — как проверяем.
- `data/README.md` — таблицы баланса и формулы между ними.
- `docs/tasks/` — задачи и их статус (`docs/tasks/README.md`). `docs/research/README.md` — разбор оригинала и решения Никиты.

## Команды
- `npm run dev` — сервер разработки: http://localhost:5173, адрес для телефона Vite печатает строкой Network.
- `npm run data` — проверка таблиц `data/*.csv` и `translations/strings.csv`.
- `npm run test` — тесты Vitest (`tests/unit`).
- `npm run build` — проверка типов, сборка в `dist/` и отчёт о размере (бюджет — 3 МБ сжатых данных).
- `npm run e2e` — смоук Playwright по собранной игре в двух раскладках, снимки в `build/shots/`. Браузер тестов рисует игру без видеокарты и грузит процессор, поэтому браузер один (`workers: 1`). При отладке гоняй один файл (`npx playwright test tests/e2e/<файл>`), полный `npm run check` — в конце задачи.
- `npm run sim` — бот «человек» на ядре без браузера: ворота M0 и кривая темпа, отчёт в `build/sim/tempo.md` (около 30 с; в `npm run check` не входит).
- `npm run check` — всё вместе. Перед отчётом по любой задаче он должен быть зелёным.
- `npm run publish` — сборка по ссылке для телефона: отправляет `dist/` в открытый репозиторий `tide-play` (GitHub Pages). Запускает Никита; Claude Code проверяет только `npm run publish -- --dry-run`.

## Устройство
- `src/core/` — правила игры: чистый TypeScript без PixiJS, DOM, localStorage, часов браузера и `Math.random()`. Время — только игровые миллисекунды из фиксированного шага (`FixedStep`, 60 шагов в секунду). Случайность — только `Rng` с сидом.
- Координаты мира — точки дизайна, начало координат — центр центральной клетки плота (моряк начинает в ней); поле видимости — 1280×720 или 720×1280 вокруг центра. Бросок, круг дальности и возврат сети считаются от точки моряка.
- `src/data.ts` — таблицы для игры и тестов (CSV через `?raw`, разбор — `src/core/data/`).
- `src/game/` — отрисовка PixiJS и слой ввода (нажатия → команды ядра); правил не решает.
- `src/ui/` — окна, полосы и кнопки: вёрстка поверх холста.
- `src/platform/` — слой площадки: с SDK площадок игра говорит только через интерфейс `Platform`.
- `src/debug.ts` — `window.__game` для тестов и ботов: не удалять, расширять по задачам.

## Правила
1. Всё, что зависит от времени (поток, таймеры, полёты, значки опыта), считается в игровом времени, а не в кадрах: за долгий шаг происходит столько событий, сколько положено по времени.
2. Числа баланса — только из таблиц `data/*.csv`, не из кода. После правки таблицы — `npm run data`.
3. На каждый модуль ядра — тесты Vitest; новая механика приходит с тестом, который без неё падает. Числа в тестах механики берутся из `DATA`, а не вписываются.
4. Файл — не длиннее 400 строк.
5. Всё состояние партии — таймеры, предметы в воде, полёты, очереди, `Rng` — входит в снимок: `snapshot()` и `restore()` у модулей ядра (с M1-01). Новое поле ядра — сразу в снимок и в `tests/unit/save.test.ts`; у старой записи без этого поля `restore` берёт значение по умолчанию.
6. В окне выбора всегда есть хотя бы одна доступная карточка, в том числе после обновления за рекламу.
7. В коде игры нет сетевых запросов, кроме SDK площадок в адаптерах.
8. Строки интерфейса — через `translations/strings.csv` (ru, en); текст в код окон не вписывать.
9. Ввод — командами ядра (`throwTo`, `setPull`…): бот подаёт те же команды, что и палец.
10. Интерфейс до этапа арта (M4) — рабочая заготовка: окно помещается на экран в обеих раскладках, всё нажимается, случайного выбора двойным нажатием нет. Вид и пиксели не вылизывать.

## Порядок работы
- Задачи лежат в `docs/tasks/`, статус — в `docs/tasks/README.md`. Делать только то, что написано в задаче; спорное — в отчёт, а не в код.
- В конце задачи: `npm run check`, строка статуса «сделано ДД.ММ» в `docs/tasks/README.md`, отчёт: что сделано, итоги `npm run check`, что не получилось и почему.
- Не коммитить и не пушить: это делает Никита.
- Windows и PowerShell: пути с пробелами — в кавычках; в npm-скриптах нет bash-синтаксиса.
