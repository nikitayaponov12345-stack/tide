# CLAUDE.md — правила для Claude Code в проекте «Прилив»

## Что это
Браузерная 2D-игра (рабочее название «Прилив»): база стоит в потоке предметов, игрок ловит их сетью, получает уровни и выбирает карточки улучшений. Жанр — по мотивам Sea Catcher (Poki), но мир, модели, интерфейс, тексты и баланс свои.
Площадки: Яндекс Игры, CrazyGames и Playgama — одна сборка; Poki — отдельно (веб-эксклюзив).
Разбор оригинала и решения по своей игре — `docs/research/README.md`.

## Команды
- `npm run dev` — сервер разработки: http://localhost:5173, адрес для телефона Vite печатает строкой Network.
- `npm run test` — тесты Vitest (`tests/unit`).
- `npm run build` — проверка типов, сборка в `dist/` и отчёт о размере (бюджет — 3 МБ сжатых данных).
- `npm run e2e` — смоук Playwright по собранной игре в двух раскладках, снимки в `build/shots/`.
- `npm run check` — всё вместе. Перед отчётом по любой задаче он должен быть зелёным.

## Устройство
- `src/core/` — правила игры: чистый TypeScript без PixiJS, DOM, localStorage и часов браузера. Время — только игровые миллисекунды из фиксированного шага (`FixedStep`, 60 шагов в секунду). Случайность — только `Rng` с сидом.
- `src/game/` — отрисовка PixiJS: читает состояние ядра и рисует, правил не решает.
- `src/ui/` — окна, полосы и кнопки: вёрстка поверх холста.
- `src/platform/` — слой площадки: с SDK площадок игра говорит только через интерфейс `Platform`.
- `src/debug.ts` — `window.__game` для тестов и ботов: не удалять, расширять по задачам.

## Правила
1. Всё, что зависит от времени (поток, таймеры, события), считается в игровом времени, а не в кадрах: за долгий шаг происходит столько событий, сколько положено по времени.
2. Числа баланса — из таблиц данных (появятся в M0), не из кода.
3. На каждый модуль ядра — тесты Vitest; новая механика приходит с тестом, который без неё падает.
4. Файл — не длиннее 400 строк.
5. Таймеры событий входят в сохранение.
6. В окне выбора всегда есть хотя бы одна доступная карточка, в том числе после обновления за рекламу.
7. В коде игры нет сетевых запросов, кроме SDK площадок в адаптерах.
8. Строки интерфейса — через таблицу переводов (ru, en), когда она появится; текст в код окон не вписывать.

## Порядок работы
- Задачи лежат в `docs/tasks/`, статус — в `docs/tasks/README.md`. Делать только то, что написано в задаче; спорное — в отчёт, а не в код.
- В конце задачи: `npm run check`, строка статуса «сделано ДД.ММ» в `docs/tasks/README.md`, отчёт: что сделано, итоги `npm run check`, что не получилось и почему.
- Не коммитить и не пушить: это делает Никита.
- Windows и PowerShell: пути с пробелами — в кавычках; в npm-скриптах нет bash-синтаксиса.
